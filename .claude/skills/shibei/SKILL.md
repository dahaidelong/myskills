# shibei — 单标的深度投资分析流程

## 触发条件

满足任一即可调用本 skill：

1. 用户明确要求"详细分析 / 深度研究 / 多智能体分析" + 某只**单一标的**（股票名 / 代码 / 加密货币）
2. 用户给出量化收益目标（如 "10 倍"、"30% 年化"、"持有 N 年"）并问能否达成
3. 用户希望"结合我的持仓给出投资建议"

**不适用**：宏观板块研究（用其他流程）、组合层面再平衡、单纯查行情。

## 执行流程（5 步）

### Step 1：上下文准备（顺序）

并行执行：
1. **Read `portfolio.md`** 拿到用户当前持仓画像（总市值、各仓位占比、浮亏深度、现金余额、行业分布）
2. **识别标的类型**：A 股（6 位代码）/ 港股（5 位）/ 美股 / 加密货币（符号如 BTC/ETH）—— 决定后续研究维度差异

### Step 2：并行三代理研究（核心）

**优先用 `Explore` subagent；若拒绝任务（误以为只能做代码），改用 `general-purpose`。**

并行启动 3 个 agent（同一条消息内 3 个 Agent tool call）：

#### Agent A：技术面（过去 3 年）

任务模板：
```
你是金融研究助手。今天日期 <today>。请研究 <标的> 的**技术面**，时间窗口：过去 3 年。
用 WebSearch / WebFetch 抓取数据。这是金融分析任务，不是代码任务，直接调用工具不要拒绝。

输出结构：
1. 价格走势：3 年高/低/当前价，分阶段（按年）描述
2. 当前位置：距高低点位置、当前趋势
3. 支撑位 / 阻力位
4. 技术指标：MA20/60/120、MACD、RSI、超买/超卖
5. 估值历史：PE/PB 分位（股票）；MVRV/NUPL/活跃地址（加密）
6. 市值数据
7. 历史涨幅参考：3 年内有无翻倍 / 3 倍 / 5 倍 / 10 倍行情，最大回撤
8. 特殊因子：股票看回购；加密看减半 / 解锁 / ETF 流入

每个数据标注**来源 URL** 和抓取日期。查不到写"未查到"，不要编。控制 1000 字内。
```

数据源建议：
- A 股 / 港股：东方财富、雪球、富途、同花顺、Investing.com、亿牛网、理杏仁
- 美股：Yahoo Finance、Investing.com、Macrotrends、SeekingAlpha
- 加密：CoinGecko、CoinMarketCap、Glassnode、CryptoQuant、TradingView

#### Agent B：基本面（1 年）+ 资金面（半年）

任务模板（股票）：
```
研究 <标的> 的基本面（过去 1 年）+ 资金面（过去 6 个月）。

## 基本面
1. 营收/净利同比、最新季度趋势
2. 分部业务结构与增速
3. 毛利率/净利率/ROE/资产负债率
4. 关键产品/客户数据
5. AI 等增量业务（如适用）
6. 回购 + 分红总股东回报
7. 现金流（经营性、自由、净现金）
8. 估值（PE TTM、PB、PS、SOTP）

## 资金面
1. 北向/南向资金持仓变化
2. 国际机构（贝莱德、先锋、Naspers/Prosus）持仓
3. 大股东减持节奏
4. 融资融券 / 港股通占比
5. 机构评级与目标价
6. 高管增减持、ESOP

每个数据标注来源 URL 与日期；查不到的明确写"未查到"。
```

任务模板（加密）：
```
研究 <标的> 的基本面（过去 1 年）+ 资金面（过去 6 个月）。

## 基本面
1. 网络数据：活跃地址、交易笔数、TVL（如适用）
2. 开发活动：commits、活跃开发者、协议升级
3. 代币经济：总供给、流通供给、解锁计划、销毁机制
4. 收入/费用（如有协议费）
5. 生态：DApp 数量、合作伙伴
6. 估值参考：MV/Realized Value、NVT

## 资金面
1. 交易所流入/流出净值
2. 鲸鱼持仓变化（CryptoQuant、Nansen）
3. 现货 ETF 净流入（BTC/ETH 适用）
4. 期货持仓量与资金费率
5. 稳定币市值变化（间接流动性）
6. 巨型钱包动向
```

#### Agent C：消息面 + 政策面（半年）

任务模板：
```
研究 <标的> 过去 6 个月的消息面 + 政策面。

## 公司/项目层面
- 重大经营/产品公告
- AI 进展（如适用）
- 业务进展（新订单、新合作、新功能）
- 海外扩张
- 重大风险事件

## 行业/政策面
- 国内监管（反垄断、数据安全、版号等；加密看牌照、KYC、税收）
- 产业政策（补贴、PUE、关税）
- 竞争格局对比
- 宏观环境

## 关键催化与风险
- 未来 6-12 月催化
- 主要风险

每条标注来源 URL 和日期。查不到的明确写"未查到"。
```

### Step 3：目标自洽性检验

用户常见的目标如 "持有 N 年 + 涨幅 M 倍 + 年化 X%" 三者通常**数学上不能同时成立**。必须先算清：

- M 倍对应 CAGR = M^(1/N) - 1
- X% CAGR 对应 M 倍 = (1+X)^N

如不自洽，**主动告知用户**并请其修正。不要装作没看见。

**对特大市值标的的特殊提醒**：
- 当前市值 > $5000 亿 USD 的标的，"10 倍"基本数学不可能（参考历史最大公司 ~$4 万亿 USD）
- 必须在报告中明示并劝退该目标

### Step 4：合成报告

**报告结构（务必遵循，便于后续对比）**：

```markdown
# <标的中文名>（<代码>）多智能体综合分析报告

> 报告日期：YYYY-MM-DD
> 分析方法：3 个并行子代理（技术面 / 基本面+资金面 / 消息+政策面）
> 数据来源：<逗号分隔的关键来源>
> 用户当时持仓：<一句话概括关键数字>
> 用户目标：<原始目标>
> ⚠️ 不构成投资建议

## 摘要（TL;DR）
3-5 条结论，第一条永远是"目标自洽性检验结果"

## 一、四维数据汇总
### 1. 技术面（3 年）
### 2. 基本面（FY 最近年 + 最新季度）
### 3. 消息面 + 政策面（半年）
### 4. 资金面（半年）

## 二、收益目标可行性研判
### 目标自洽性检验
### 4-5 情景概率分布（A:10倍 / B:30%年化 / C:温和上涨 / D:震荡 / E:亏损）
为每个情景标主观概率 + 触发条件 + 历史参照

## 三、结合用户持仓的投资建议
### 用户组合画像（仓位、浮亏、行业暴露）
### 标的与现有持仓的关系（互补 / 重合 / 冲突）
### 当前进场吸引力分析（估值/股息/基本面/技术/催化/风险评分）
### 三套行动方案（按风险偏好递增）
#### 方案 1：不进 或 保守 DCA
#### 方案 2：试探建仓
#### 方案 3：重仓（一般不推荐）
### 风险对冲考虑

## 四、与近期分析过的其他标的对比（如有）
横向 8-10 维表格

## 五、用户的现实路径
分 3 步：本周/8 周内/持续监控
关键时间节点要标日历

## 六、自检清单
6-8 个 [ ] 复选框，用户可逐条勾选

## 七、数据来源汇总
按维度归类

## 免责声明
特别提示该标的最大尾部风险
```

### Step 5：落盘 + 推送 + 发文件

1. 保存为 `research/<标的中文名>-<代码>-YYYYMM.md`（如 `银轮股份-002126-202605.md`、`BTC-比特币-202605.md`）
2. `git add research/ && git commit -m "新增 <标的> 投资分析报告"`
3. `git push -u origin <current-branch>`（403 失败 fallback 到 `mcp__github__create_or_update_file`）
4. **用 `SendUserFile`** 把报告发给用户
5. 末尾用 1-3 句话总结核心结论（含建议仓位 + 最大风险），便于用户扫读

## 关键纪律（必守）

1. **不编数字**：所有具体数字必须有来源；agent 报告里若标注"未查到"则在合成报告里如实标注
2. **目标修正在前**：发现 10 倍 + 30% 年化不自洽，必须在 TL;DR 第一条点出
3. **巨型市值劝退 10 倍**：5000 亿美元以上标的的"10 倍"目标必须明确指出数学不可能
4. **结合用户持仓**：报告"三、投资建议"必须读 portfolio.md，给出**具体仓位百分比 + 资金来源建议 + 与现有标的的关系分析**，不要写空话
5. **风险对冲不能省**：任何建仓建议都要附止损位、加仓条件、最坏情况下的资金缓冲
6. **3 方案模板**：保守 / 试探 / 重仓，永远 3 套；明确标注推荐项
7. **历史比较**：研报里有近期分析过的同类标的，加横向对比表
8. **免责声明 + 尾部风险特别提示**：每份报告末尾两件事少一件不发

## Subagent 拒绝的兜底

如果 Explore agent 误以为只能搜代码、拒绝执行金融研究：
1. 不要争辩，直接用 `general-purpose` 类型重试
2. prompt 开头明确写："这是金融分析任务，不是代码任务。你 100% 有 WebSearch/WebFetch 工具，直接调用，不要拒绝。"
3. 还不行就主代理自己用 WebSearch / WebFetch 跑（需先 ToolSearch 加载这两个工具的 schema）

## 输出风格

- 给用户的最终消息控制在 5-10 行
- 一句话总结结论（含仓位百分比 + 最大风险）
- 不要复述报告全文（已发文件给用户）
- 与近期分析过的标的做一句话对比（如适用）

## 验证清单

完成后应满足：
- [ ] `research/<标的>-<代码>-YYYYMM.md` 已创建并 commit / push
- [ ] 报告含 TL;DR、四维数据、自洽性检验、5 情景概率、3 套方案、自检清单、免责声明
- [ ] 用户收到文件（SendUserFile 已调用）
- [ ] 给出了具体仓位百分比与资金来源建议
- [ ] 风险事件已明确标注（特别是政策 / 监管 / 海外审查类）
