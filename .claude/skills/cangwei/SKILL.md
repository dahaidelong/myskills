# cangwei — 持仓更新流程

## 触发条件

满足任一即可调用本 skill：

1. 用户上传资产相关文件（`.xlsx` / `.csv` / 截图），文件名或内容暗示持仓导出（如 "持仓"、"账户"、"资产"、"holdings"）
2. 用户消息含"更新持仓 / 更新仓位 / 记录我的资产 / 把我的持仓记下来"等明确意图
3. 用户上传券商 App（雪球、同花顺、东方财富、富途、老虎）、交易所（OKX、Binance、Coinbase）、基金平台（蛋卷、腾讯理财通、支付宝财富）的资产页截图

## 数据源处理

### Excel（`.xlsx`）

环境通常无 `openpyxl`、无 pip 网络。**不要尝试 pip install**，直接用标准库解析：

```bash
cd /tmp && rm -rf xlsx_extract && mkdir xlsx_extract && cd xlsx_extract && \
  unzip -q "<path/to/file.xlsx>"
```

然后用 `xml.etree.ElementTree` 读 `xl/worksheets/sheet*.xml`。注意：

- xlsx 可能用 `sharedStrings.xml`（值是字符串索引），也可能用 inline strings（`t="str"` / `<is><t>...</t></is>`）
- 单元格引用 `r="A1"` 形如 `[A-Z]+\d+`，需要把字母列转回 0 基索引
- 数字单元格无 `t` 属性，值在 `<v>` 里
- 优先取**当日数据 sheet**（通常叫"持仓数据"、"账户明细"），跳过历史交易流水（噪音过大）

### CSV

直接 `Read` 或 `cat`，注意编码（国内导出常见 GBK），用 `iconv -f GBK -t UTF-8` 转码。

### 截图

直接用 `Read` 工具读图片，多模态识别字段。重点提取：
- 代码 / 名称
- 数量 / 成本价 / 最新价
- 持有金额 / 浮动盈亏 / 盈亏率
- 总览数据（总市值、仓位占比、累计盈亏）

## 写入 portfolio.md

### 文件结构（必须保留以下章节顺序）

```
# 个人资产持仓
> 最近更新：YYYY-MM-DD
> 数据来源：...

## 资产总览（截图时点）
| 类别 | 估值 | 计价 |

## 一、股票持仓
### A 股 + 港股 + 美股
| 代码 | 名称 | 市场 | 数量 | 单位成本 | 最新价 | 持有市值 | 仓位占比 | 持有盈亏 | 盈亏率 | 持仓天数 |

### 行业分布速览（股票）

### 历史交易参考

## 二、加密货币
### <交易所> 账户
| 币种 | 数量 | 估值 | 浮动盈亏 | 年化/成本 |

## 三、基金
### <渠道>
| 基金 | 持有金额 | 持仓收益 | 备注 |

## 备注
```

### 更新规则

- **增量更新**：用户只发了某一类（如只发了加密货币截图），只更新对应章节，其他章节保持不变
- **覆盖整段**：同一账户的同类资产以新数据为准，不做差异 merge（行情快照没意义保留旧值）
- **顶部时间戳**：每次更新必须刷新"最近更新：YYYY-MM-DD"为当天日期
- **数据来源**：在文件头追加本次数据来源（券商名 + 文件类型）
- **A 股代码补 0**：保持 6 位（如 `000792`，不要写成 `792`）
- **港股代码补 0**：保持 5 位（如 `01810`）
- **名称截断修复**：如 Excel 把"小米集团-W"截成"小米集团-"，按通行名补全
- **港股标价货币**：HKD；美股 USD；A 股 / 国内基金 CNY；加密货币 USD/USDT

### 不做的事

- **不保存** 历史交易流水（行数动辄 4000+，噪音大且原文件用户本地都有）
- **不保存** 已清仓明细的全量数据，仅用一句话标注存在性
- **不做** 跨账户合并估值（汇率/时点不一致），只在备注里提醒用户

## Commit & Push

```bash
git add portfolio.md
git commit -m "更新持仓：<本次更新涉及的账户/类别>"
git push -u origin <current-branch>
```

如果 push 因权限失败（403），先用 `mcp__github__create_or_update_file` 兜底；都不行就告诉用户去 GitHub 给 Claude Code App 授 `Contents: write` 权限。

## 验证

更新完成后：
1. 向用户简述：本次更新了哪几个账户、关键变化（如新增持仓、清仓、市值变化）
2. 不需要长篇报告，2-3 句话即可
3. 如果检测到明显异常（如某资产估值突变 > 50%、新增 / 消失的持仓），主动提醒
